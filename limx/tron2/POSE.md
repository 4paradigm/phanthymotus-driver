# TRON2 pose预设动作

0.8.0新增独立`pose`卡片。只显示`pose`、`side`、`speed`，没有自定义关节、action或内部追踪字段。arm_control继续只公开move/reset。

| pose | 动作 | side |
|---|---|---|
| salute | 屈肘、抬臂敬礼示意，停留后回正 | left或right，默认right |
| wave | 抬臂、小幅侧摆两次，随后回正 | left或right，默认right |
| welcome | 双臂适度展开、停留后回正 | 固定both；忽略表单中声明过的左右侧残留 |
| reset | 回到原自然垂下home | 固定both |

speed为slow（默认）或normal，按最大关节行程分别以4或6度/秒计算计划时长，每段至少2秒，最终回正至少8秒。厂家插补曲线未标定，此数值不是实测速度保证。每次只执行一套动作，不自动循环。

```json
{"pose":"wave","side":"right","speed":"slow"}
```

敬礼、挥手、欢迎要求：原home身份/固件匹配，home接近DACH_TRON2A自然垂下基准；双臂实际在home误差1度内且反馈完整/静止；头部静止且俯仰/偏航均在正前方±10度内。先用reset回正，必要时用move_head调整朝向。全程保持头部及夹爪开口，不调用夹爪或头部运动接口；TRON2夹爪只能做敬礼示意，不提供五指手型。

## 执行与完成

pose与arm_control共用同一个ArmCompletion owner；头部和两侧夹爪的既有互斥仍有效。整套序列只有一个action_id和一次终态ACP，tool=pose。抬臂、停留、侧摆、回正之间不会释放owner。任一段须收到精确厂家成功ACK，再等待计划时长、推进的厂家时间戳以及至少3次稳定到位反馈；各关节误差不超过1度，稳定窗口至少0.5秒。完成所有段并核实原home后才报告completed/at_home。

缺值、未知姿态、错误侧别、错误速度、自定义关节或旧action请求均在控制权审核和运动之前拒绝。完整动作序列在首段发送前验证关节限位和300秒ACP预算；不存在边执行边发现后面一段越界的行为。规划在工作线程运行，避免阻塞反馈接收。

每段前核对原连接/序列号、新鲜静止反馈、上一段目标、机器人可用状态、VR头部跟随已关闭及本机15794遥操active/output_active均关闭。厂家VR开关只读，不自动切模式。已知遥操端口明确拒绝连接时认为该本机服务未监听；超时、异常响应或未知状态拒绝。此检查不等于跨进程硬件控制权协议，其他运动来源仍需在现场停用。

首段明确拒绝或纯发送前审核失败，不产生粘住的任务。发送/回执不明、断连、到位失败或ACP送达失败，会取消所有后续帧并保留共享owner及失败记录，不重发、不强行回正。head/home变化也会取消后续段；原home文件不会被改写。

平台内部stop取消未发送的后续帧；已发送的一段仍需反馈确认到位后才报告cancelled并释放owner。stop不是硬件急停。关进程、反馈丢失或当前段失败时仍报告不确定，不声称实体停止。启动/部署/发现/info不执行姿态。

## 模型与验证范围

动作角度依据本项目固定版本TRON2官方URDF重新设计。Q5/Adam的语义动作与序列组织仅作结构参考，没有复制它们的关节值、手型、通信或宽松ACP实现。

规划用TRON2正运动学，对关节线性参考路径每不超过2度采样；远端骨架保持在各自侧方，避开参考头部中心的0.20m禁入球。nominal肩旋转取±84.5度，避免精确85度略超SDK四舍五入的1.4835rad边界。校验原home容差3度，不改原home。

该URDF没有真实碰撞几何；骨架排除区不是完整自碰撞、外部桌面或厂家实际插补轨迹验证。结果始终collision_checked=false、physical_presets_verified=false。现场首次须空载、清空整个运动范围、slow低速逐个验收。部署不会自动执行敬礼、挥手、欢迎或回正；软件测试通过不代表实际外形、动作美观度或物理安全已经验收。

本地覆盖所有动作/侧别/速度的限位和参考路径、共享任务互斥、每段到位、失败取消、生命周期停止、断连/回执/回调保护、非法输入不发运动，以及真实回环MCP/WebSocket/ACP。源码新增pose.py，复用原MoveJ发送路径，无新运动协议、依赖包、Core或其他机器人改动。
