# 头部转动 move_head

在 Motus 中添加 `move_head` 卡片，直接填写两个绝对目标角度和运动时间，无需选择 action：

| 参数 | 含义 | 范围 |
| --- | --- | --- |
| pitch_deg | 头部上下俯仰角度（°） | -45～60 |
| yaw_deg | 头部左右转动角度（°） | -90～90 |
| time | 运动时间（秒） | 0.1～60，默认5 |

两个角度都须明确填写，没有预设姿态。正负方向按厂家坐标系；仅改变俯仰时，
将偏航填写为当前实际偏航角，不能将缺省偏航当作自动保持。`joint_state` 的
头部反馈对应索引14（俯仰）、15（偏航）。`info` 可通过 MCP 只读获取这两个
当前角度；不新增公开的 get_state 菜单。

卡片输入为度，驱动转换为 rad，仅发送一次厂家的 `request_moveh`，数组顺序
固定为 `[pitch, yaw]`。不会发送双臂14项目标、夹爪指令、升降台或模式切换。
现有 `arm_control` 的 move/reset 仍只控制双臂。

限位依据 TRON2 双臂形态用户手册1.5及厂家 DACH URDF。SDK网页中的 rad 值
写为近似值（俯仰-0.78～1.04、偏航-1.57～1.57），与手册精确角度存在舍入
差异；这里保留手册的度数和标准弧度换算。实机若拒绝端点，不会夹取、重发
或宣称到位。实际端点尚未通过实体运动验证，不建议首测直接走到限位。

## 完成结果与互斥

`state: moving` 和 `motion_sent: true` 仅表示已受理，不代表已经到位。
驱动必须收到与请求 GUID、机器人身份、响应类型一致的成功回执；运动时间
结束后，同一连接上的头部反馈时间戳持续增加，两轴目标误差不超过1°，
位置稳定且原始速度反馈接近零，至少3个新样本、跨度不小于0.5秒，才通过
ACP 报告 `completed`、`arrival_verified: true`、`head_target_verified: true`。
反馈测量时钟没有验证，接收年龄与厂家时间戳分开使用，不宣称绝对测量年龄。

双臂、头部、夹爪任务之间互斥。头部开合角度本身不会锁住其他动作；未完成、
结果不确定或完成回调未送达的头部任务会保留本地保护。断连、过期反馈、
重复时间戳、未到位及回执不明不会转为完成，也不会自动重试。

`start`/`stop` 仅为平台生命周期，不转动头部；`stop` 不是硬件急停。
驱动启动、注册、镜像验证、部署检查不会自动执行头部运动。

0.7.1起，卡片仅显示pitch_deg、yaw_deg、time，后端缺省执行move。ACP声明不设
action过滤，因而没有action字段的正常转动仍建立异步完成跟踪。info/start/stop
仍供平台内部生命周期使用，这些返回不含action_id，不会建立虚假的待完成任务。
发生失败时，health.head_motion和后续拒绝结果会保留原任务错误、成功回执标志、
目标角度与当前反馈；不会仅给出泛化的机械臂忙提示，也不会自动解除保护。

每次发送MoveH前，驱动从同一机器人主机的厂家HTTP8888 `/get_robot_info` 读取
新鲜头部跟随状态。必须有有效的 `enable_vr_follow_head=false` 和上层开发模式；
VR跟随开启、状态缺失或读取失败时，在发送前拒绝，不产生新的运动任务保护锁。
驱动不会自动关闭VR跟随、切换模式或绕过它改用其他运动接口。VR头部跟随是
机器人全局设置，改变前需协调正在使用该功能的开发者。

参考：[厂家 SDK 3.6.2 MoveH](https://www.limxdynamics.com/zh/documents/847884267345285120)。
