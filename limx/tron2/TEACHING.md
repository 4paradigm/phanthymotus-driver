# TRON2 原厂 VR 录制、回放与 VLA 导出

`tron2_teaching` 使用 G1 teach 的公共工作台和动作包服务。录制器只发送关节和夹爪查询，并读取三路 MJPEG。开始录制、停止录制和保存训练数据均不发送运动命令，不进入或退出原厂 VR。

Core 必须包含工作台托管与卡片动作过滤（Core 提交 `b00075b0`）。卡片 ACTION 仅显示录制技能、运行技能、preview、导入动作包、导出动作包；数据质量、标注和训练导出位于工作台内。旧 Core `release.261014.03ced4b` 会显示所有内部动作，不能只更新 Driver。

实体回放由操作者逐次确认独占。执行前退出原厂 VR，停止其他控制程序，核对起点与活动空间，并在确认弹窗中勾选确认。API 对应 `exclusive_control_confirmed=true`；缺失或 false 时不发送动作。该确认不是硬件租约，软件不检测其他进程是否重新接管；操作者须在回放期间保持独占。

## 数据来源

双臂录制值允许超出当前厂家命令限位最多 5°。回放预检将容差内的值限幅到原命令范围，起点检查与后续发送均使用限幅后的目标；超过容差则拒绝整段。原始录制、训练数据与动作包导入导出保留实测值。直接 MoveJ/ServoJ 命令不放宽限位。

起点差异用于预览，不要求用户手动摆到首帧。用户确认移向起点的路径、夹爪动作和回放活动空间后，程序先核验静止反馈，再发送一次厂家 MoveJ 到首帧。时间复用回位规则：`max(8, ceil(最大关节差/5°))/1.2` 秒，超过厂家 60 秒单次上限则拒绝。即使当前位置已接近起点，也先用 MoveJ 建立厂家位置目标，再使用 ServoJ。

MoveJ ACK 只表示接收；程序等待完整运动时长，并核验双臂距首帧各不超过 2°、反馈持续静止至少 0.5 秒。双臂到位后，用用户填写的速度和力档位调整夹爪，并检查开口误差各不超过 3 个厂家单位且夹爪速度为零。只有全部通过才开始原轨迹计时。移到起点和夹爪检查分别有 10 秒额外到位等待与 30 秒上限；失败、断线或取消均不进入回放。停止取消后续步骤，不保证厂家立即停止当前 MoveJ 或夹爪运动；停止确认不足时保持占用。

MoveJ 准备目标另外受厂家控制器范围约束。[厂家固定版本测试模型](https://github.com/limxdynamics/tron2_manipulation_controller/blob/482ebbc284dc2601eafec7130820bbfbe710c4e9/Tron2_arm_tests/dual_arm_protocol_tests/robot_model.py)的 CONTROLLER_ARM_LIMITS 比 SDK 范围更窄，腕俯仰和腕滚转均为 ±0.7505 rad。准备阶段取两个范围的交集；只允许在既有 2° 起点容差内调整 MoveJ 目标，超过则预检拒绝。工作台显示最大调整角度；录制和 ServoJ 执行帧不受此 MoveJ 调整影响。现场 2026-10-22 的右腕滚转首帧 -0.7837003 rad 被厂家拒绝，准备目标改为 -0.7505 rad，相差 1.90224°。当前现场库摘要和 soft_limit 参数尚未核对，不把公开库与现场版本声明为完全一致。

动作正常完成后自动解除占用。失败或取消时，若 MoveJ 已确认接受且没有未确认的夹爪发送，程序等待 MoveJ 规划时长结束，再进行最多 3 秒的只读静止检查：同一连接、反馈新鲜且时间戳推进、双臂与头部位置持续稳定至少 0.5 秒、关节低速、双夹爪静止。通过后自动解除占用，但保留失败或取消结果，不恢复回放。连接变化、反馈冻结、持续运动或发送结果不明时保持占用。

工作台常驻“手动解锁”按钮；动作执行、恢复检查、录制或断线时禁用。操作者确认机器人已停止且 VR/其他控制已退出后，调用 unlock（physical_stop_confirmed=true、exclusive_control_confirmed=true）。未到 MoveJ 的保守等待时间仍拒绝；随后重新读取静止反馈，成功才解除占用并清空旧预览。解锁不发送急停、模式切换或运动命令，不改变试运行失败结果；必须重新检查起点再试运行。静止反馈是软件观察，不是硬件独占证明。

5° 录制容差不放宽到位要求。预览有效期为 60 秒，执行时重新检查。头部保持执行开始时的角度。工作台显示检查、移向起点、调整夹爪、核验到位和回放阶段。

回放还要求 developer_mode、碰撞保护开启、拖动模式关闭、电机 OK、无其他运动占用。录制时间戳必须递增，相邻间隔不超过 100 ms。运行中反馈不得陈旧超过 100 ms，发送延迟超过 50 ms 不追帧；双臂跟踪偏差超过 8°、头部偏差超过 2°、夹爪偏差超过 15 个单位会中止。最后一帧后最多等待 5 秒核验到位和静止。用户仍须现场退出 VR 并确认独占；这些检查不能证明零输出接管问题已经修复。

起点检查和回放计时开始前临时提高只读关节查询频率，最多等待 0.5 秒取得不超过 100 毫秒的反馈。超时仍拒绝回放，不放宽反馈或起点限制。未发送指令的启动失败不会留下运动占用。

2026-10-21 在指定 TRON2 上执行有界只读查询，每类 50 次、目标周期 20 ms；每路相机读取 20 帧。它们是独立短采样，不是原厂 VR 示教验收。

## 保存内容

默认容器目录为 `/data/tron2-teaching`，可通过部署配置中的 `TRON2_TEACHING_DIR` 指定。部署片段新增独立可写数据挂载，原 home 配置仍只读。

每个 `episodes/<id>/` 保存：

- `manifest.json`：`motus.tron2.episode/1`、设备序列号、固件、URDF SHA、关节顺序、单位、任务、结果、备注、来源与质量。
- `trajectory.jsonl`：关节 q/dq/tau、双夹爪原始反馈、源时间、接收单调时间、接收墙钟时间、序号及原厂目标可用性。
- `head.mjpeg`、`left_wrist.mjpeg`、`right_wrist.mjpeg`：原始 JPEG 包按接收顺序连接，不重新编码。对应 `.jsonl` 保存逐帧序号、时间、字节位置和长度。
- `complete.json`：在所有文件 fsync、清单写入及目录同步之后写入；绑定清单 SHA。清单包含各数据文件的大小和 SHA256。

写盘线程使用有界队列，磁盘余量至少 256 MiB，最长 30 分钟，轨迹上限 64 MiB。溢出、时钟倒退、相机断流或关节断流结束录制并保留失败数据，不自动删除。重复源时间的关节样本不重复写入。三路图像或夹爪缺失时，不能标记为完整训练 episode。

源时间未验证，首版统一在同机单调接收时钟上对齐。不声称曝光同步或硬件同步。

## 工作台和训练导出

1. 在卡片打开工作台并检查设备。
2. 点击“开始录制”，在弹窗填写任务描述。确认后开始只读录制，再使用原厂 VR 示范。
3. 结束录制后进入试运行页。展开“训练数据”，点击“打开训练数据”进入独立页面。
4. 查看质量，补充成功、失败或未标注结果与备注，点击“保存标签”。随后可直接导出 LeRobot v3，不要求机器人回放。

主流程固定为“设备检查 → 录制 → 试运行 → 保存”。训练数据页面提供返回入口。历史录制中的“查看数据与诊断”也打开此页面。未完成录制只显示诊断，禁用标签保存和训练导出。

试运行前在弹窗填写夹爪速度与力档位，并勾选独占确认。每次打开弹窗都会清空夹爪参数；空值或无效值不会关闭弹窗。

![390px 视口中的回放确认弹窗](resource/teaching-confirm.png)

固定使用官方 `lerobot==0.4.4`（Apache-2.0）的 `LeRobotDataset.create/add_frame/save_episode/finalize` 和读取接口，输出 H.264 三路视频。导出完成后逐帧读取并解码三路图像，检查 state/action 形状和归一化统计。失败目录保留，已有目录不覆盖。

- `observation.state` / `action`：左 7、右 7、左夹爪、右夹爪；前 14 项 rad，后 2 项厂家无量纲开口。
- 当前真实采集使用 `measured_future_state`：10 Hz 训练帧的下一时刻实测状态作为绝对动作，派生间隔 0.1 秒。末尾没有未来状态时不生成动作。
- 图像选择当前时刻之前最近的帧，最大误差 50 ms；关节只在间隔不超过 100 ms 的相邻样本之间插值。夹爪使用最近过去值，不插值。
- 无效点排除，缺口两侧分成独立训练 episode；不压缩时间后拼成一条运动。
- `observation.head`、`source_time_ns`、`action_time_ns`、结果标签和任务保留在数据集；原始时间、来源和所有 episode 校验信息保存在导出报告及原 episode。
- 数据集目录对应一个来源 episode，只有一个动作来源；不混合派生动作和原厂目标。成功读取不证明训练效果。

## 与 G1 teach 的界面关系

复用 PR #412 固定版本的同一工作台页面和草稿/试运行/效果确认/Skill 保存服务，不是逐项完全相同的界面。

| 流程 | G1 teach | TRON2 |
| --- | --- | --- |
| 检查与录制 | 检查、启动 G1 遥操/映射、录制 | 检查、由用户启动原厂 VR、只读录制 |
| 录制后 | 试运行 | 试运行；折叠入口打开独立训练数据页面 |
| 动作保存 | 试运行成功、人工确认效果、保存 Skill | 相同约束 |
| 导入动作包 | 导入待验证、试运行、确认启用 | 相同约束；试运行前增加夹爪参数和独占确认弹窗 |
| 新增内容 | 无 TRON2 数据集字段 | 任务/结果/备注、三路图像质量、LeRobot 导出 |

训练导出不替代动作试运行。停止录制不停止原厂 VR。TRON2 不启用逐技能自动执行。

## 回放与动作包

轻量回放使用 `motus.tron2.trajectory/1`，不复用 G1 十关节 schema。外层动作包仍是原有两文件 ZIP，不含视频；训练导出直接读取完整 episode。

回放执行器校验文件、模型和设备绑定、关节限位、时间连续性、2° 起点差异及夹爪开口差异。回放不设固定的录制速度上限，按录制时间戳发送原始轨迹，不自动减速。其他校验不通过时直接拒绝；起点准备按本页 MoveJ 流程执行，不切模式。夹爪速度和力档位必须明确填写，不能从实测开口推断。

头部保持开始时实时位置。控制检查、反馈检查、厂家故障、50 ms 发送迟到和停止都会结束发送；不补发积压帧、不重连自动重放。终态要求连续推进的关节反馈、低速度和双夹爪目标反馈；失败或取消保留原结果，只有后续静止检查通过才解除占用；现场物理停止仍需用户观察。回放中其他本机动作卡也受现有互斥机制约束。

每次回放都需要新的预览与人工独占确认；真实试运行成功且用户确认效果后才能保存 Skill。导入动作包只创建待验证草稿；不能通过包内声明绕过本地试运行及效果确认。

浏览器 fixture 只监听本机 15892，使用真实工作台、HTTP 和文件实现，厂家与相机为假服务。它不是 Core 部署或现场验收。使用新数据目录启动 fixture 后，在其浏览器页执行 `tests/teaching_workbench_browser.js`。脚本返回 Promise，覆盖任务必填、标签保存、轮询保护、官方训练导出、回放参数、技能保存及断流诊断；必须先安装 VLA 依赖。脚本只允许本机 fixture 页面，不能用于机器人页面。

本轮尚未完成原厂 VR 实际示教采集、真实回放、物理停止、用户效果确认或 VLA 训练。依赖中的 torchvision 视频解码接口给出弃用提示；固定版本目前通过测试，升级官方依赖时须重新验证。
