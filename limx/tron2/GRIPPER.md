# TRON2 夹爪卡片

从0.7.7起，使用一张 `gripper` 卡片，明确选择左右爪；没有action、close、recover选项。左右仍各自保留任务、反馈和完成状态。

| 参数 | 范围与含义 |
|---|---|
| side | left左爪；right右爪，必须选择 |
| opening_mm | 0至85mm的绝对目标开口；0闭合，85最大目标 |
| speed | 大于0、不超过100的速度档位 |
| force | 0至100的力档位，并非牛顿 |

```json
{"side":"left","opening_mm":40,"speed":10,"force":10}
```

四项均必填，无自动运动默认值。越界、布尔值、非数字、缺值、未知字段及旧action参数会在等待、恢复、占用任务和硬件调用之前拒绝；不创建新任务、不清除旧任务。刷新旧页面后重新填写，不复用旧表单参数。

## 单位与到位

底层目标 = opening_mm × 94 / 85，保留6位小数。0/42.5/85mm分别对应原始0/47/94。这是按标称行程建立的名义线性换算，实际间距精度待标定，`opening_mm_is_calibrated=false`。原始反馈仍为0至100，不截断；毫米反馈仅为计算估计。force不按标称20N线性换算，也不是压力传感器读数。达到开口始终不代表抓取成功，`grasp_verified=false`。

受理不等于完成。厂家确认回执后，须有推进的反馈时间戳、至少3次目标误差不超过1原始档且稳定至少0.5秒的反馈，随后通过ACP报告完成。原地重复目标只核对新鲜静止反馈，不重复写电机。MCP保留为调用传输；去掉action后使用不带actions筛选的x-completion，完成回调的tool为gripper，以action_id对应具体左右任务。

## 连续调用与失败

只发送所选侧的opening/speed/force，不给另一侧填默认值。每侧至多一条后续请求等待前序确认，最长40秒，无固定冷却时间。Core资源声明保守覆盖arm_l、arm_r（当前Core只支持静态资源），智能控制可能串行调度；驱动内部两侧任务仍独立，不清除另一侧任务。机械臂或头部任务未结束时保持运动互斥。

输入合法不保证硬件到位。断连、厂家故障、回执不明或目标未到位仍保留失败记录及必要保护。删除recover按钮不取消保护，也不允许靠任意新请求自动解锁。

明确填写0mm时，内部沿用已验证的close接替逻辑：仅原open已收到厂家确认且以target_not_reached失败、原ACP已送达、同一连接下连续新反馈确认本侧开口稳定和速度零，才允许发送一次新的闭合命令。保留previous_action_error，不把旧失败改成成功；其余不确定任务需检查实物和控制器后维护恢复。生命周期stop取消等待请求，不是硬件急停。

## 迁移与验证

默认配置及发现目录仅提供gripper。历史固定侧协议代码只用于旧配置兼容；新版默认配置不开放gripper_left/right调用。原有两张无连线卡片经备份后合并为一张，保留首张位置与ID，清除旧输入，不默认选择左右。若旧夹爪卡片有连线，部署在更新驱动前拒绝迁移，要求先明确流程用途；不静默把右爪连线改接左爪。

本地假机器人及真实回环HTTP/WebSocket覆盖左右路由、非法参数不发运动/不占任务、并发独立完成、0mm闭合和ACP回调。部署只做静止检查、源码/接口/反馈验证，不执行实体开合。实际毫米精度、物体接触与抓取性能未由这些检查证明。
