# TRON2 左右夹爪卡片

在 Motus 工具库中分别添加 `gripper_left`（左夹爪）和 `gripper_right`（右夹爪）。每张卡片固定对应一侧，无需选择SIDE。两张卡片独立跟踪任务、到位反馈与失败恢复。

| 操作顺序 | 用途 | 填写参数 |
|---|---|---|
| `open` | 调整本侧夹爪到指定开口度 | opening、speed、force |
| `close` | 闭合本侧夹爪至最小开口 | speed、force |
| `recover` | 检查连续静止反馈，恢复本侧失败任务 | 无 |

`open` 已合并原 `set_opening`，必须填写目标opening，不再固定张到100。不再提供get_state或confirm_stopped输入。新卡片默认open，但opening、speed、force没有预填值，未完整填写时不会发送电机指令；系统start/stop也不发送开合。

opening为0至100的相对开口度，0为最小闭合、100为最大张开。speed为大于0至100的相对速度档位，force为0至100的相对夹持力档位，并非毫米、毫米/秒或牛顿。请根据实物选择能够达到的目标，不能根据一次反馈假定已标定最大开口。现场曾出现目标100、反馈94，这仍是未到位；不会扩大容差或提高力档位来掩盖失败。

执行前确认机器人连接正常，处于上层开发模式。卡片不切换机器人模式。动作只向本侧发送opening/speed/force三项，不给另一侧填默认值。左侧未到位不会锁住右侧，右侧失败也不会清除左侧任务。机器人断连、厂家全局故障仍会影响两侧。

响应包含跟踪编号；厂家接受指令后，连续至少3次新查询、持续至少0.5秒，开口误差不超过1个档位且厂家时间戳逐次更新，才报告目标到位。缺少时间戳时拒绝发送。已在目标开口时，仅验证新反馈、稳定开口和零速度，不重复发送电机指令，结果为no_op=true、motion_sent=false。切换操作后网页残留的已声明隐藏字段会被过滤，不会成为电机参数；未知字段仍被拒绝。

**到达目标开口不表示抓取成功。** 物体可能阻止夹爪达到闭合目标；此时返回未到位，不宣称已经抓住物体。卡片不校准接触力或判断物体存在。

超时、回执丢失或反馈异常时不会自动重发。实际发过指令而结果不明时，本侧保留任务保护。先现场确认该夹爪已静止、空载、周围没有手或障碍物，再执行该侧recover。恢复自动检查同一连接下至少3次更新反馈、至少1秒开口稳定且本侧速度为零，并确保原任务结果已通知平台；任一检查失败都保留保护。无需确认框，不代表软件能够判断空载或现场无人。恢复只清理本侧失败任务，不重发开合，也不把原失败改成成功。

机械臂动作与两侧夹爪仍互斥：机械臂执行或结果不明时，两侧均不能开合；任一夹爪任务未结束或结果不明时，不能叠加双臂动作。每侧独立声明arm_l或arm_r资源，机械臂声明两者；这是本驱动的任务保护，不提供跨驱动硬件锁。当前版本没有遥操集成。

卡片详情/后台info与health保留反馈、任务锁、具体失败原因和can_accept_motion。系统stop、recover、关闭驱动都不是硬件急停。骨架中的夹爪轮廓仍为固定闭合示意，不是实时开合动画。

## 实现与验证

遵循仓库README_dev.md的MCP、x-action-params、生命周期和ACP完成协议，参考Revo2左右手分卡及RealMan故障检查模式，不复用其他型号硬件协议。厂家协议使用request_get_limx_2fclaw_state和request_set_limx_2fclaw_cmd，每次校验guid、accid及响应类型，通过唯一WebSocket接收循环分发。两侧使用独立任务所有者及对应工具名发送ACP完成回调。

本地测试使用假机器人和真实回环HTTP/WebSocket，覆盖并发左右开口、左侧失败不阻塞右侧、独立恢复、重复闭合不写电机、机械臂互斥、回执丢失和缓存反馈。部署仅验证状态、发现、恢复空操作、关节与视频，不自动执行实体开合。实际档位效果由现场后续调试确认。
