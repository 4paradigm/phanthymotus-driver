## 接口与卡片

- 对照 Bumi `semantic_action` 的 `actuator`、单实例、`action` 枚举和
  `x-action-params`，提供标准动作下拉框与执行按钮。
- 接入 16 个公开 Q1 上肢动作、16 个公开全身动作、`reset` 和 `status`，
  共 34 个选项。动作名称与编号已与官方接口说明、v1.1.8.0 消息包及
  机身 Q1 运控配置交叉核对。
- 不开放任意模型、轨迹路径或未经公开文档确认的动作。
- 启动/停止画布不下发运动命令。执行前检查模式、切换就绪和新鲜的直立 IMU；
  切换后再次核对状态才下发动作。并发请求不排队；丢失响应不重试。
- 服务回执显示 `accepted`，不伪造物理完成。`reset` 不是急停。
- 系统 `info` 立即返回有年龄标记的缓存；用户显式选择 `status` 刷新真机状态。

运行前加载 ROS 和消息包环境，设置 `Q1_RUN_DDS_TESTS=1`，并将仓库加入
`PYTHONPATH`（保留已加载的 ROS 路径）。完整命令见 README。

覆盖范围：

- 32 个动作的接口映射、模式切换顺序、复位和生命周期行为。
- 非站立/保护/切换中拒绝、取消后不再发动作、模式被改变时中止后续调度。
- `header.code` 与 `state` 联合判断、超时不重试、接受回执不表示动作完成。
- Core 高频 `info` 查询不创建 DDS 进程。
- Docker 构建上下文包含全部 `COPY` 所需文件。
- 真实 `aimdk_msgs` 编解码与 RPC 往返：使用固定隔离域 **93** 的模拟服务，
  核对挥手、复位、全身动作的字段、触发源和模式命令。

这些运动 RPC 测试均在模拟 DDS 域执行，没有向真机域 0 下发运动命令。

## 现场反馈后的修复（2026-11-27）

现场确认双脚着地、稳定站立，旧卡片却返回未就绪。只读对照发现：

- 高层运控没有发布原始 `/aima/hal/imu/state`，但
  `/torso_imu_orientation` 持续提供有效直立朝向。缺失数据被旧实现误报为 false。
- 同一时刻 `GetMcAction` 返回模式 1002、状态 100，但切换标志 false；
  原生 `/aima/mc/common/state` 返回相同模式和状态、切换标志 true，
  并报告未摔倒、未提起、未移动。原生 MC 消息包与公开 SDK 的 RPC 定义一致；
  `aimrt_pulsecore` 的旧消息定义缺少 source，不能替代当前 MC 定义。
- 每次请求创建客户端、仅等待 3 秒发现服务，导致冷启动易受 DDS 匹配延迟影响。
  官方接口说明 1.2.3 推荐复用客户端，并为首次匹配预留时间。

修复使用高层姿态回退，缺失或过期数据返回未知；切换标志仅由 0.5 秒以内、
且模式与状态一致的原生运控样本补齐。未移除就绪检查。
ROS 客户端由一个隔离进程复用，最多等待 8 秒发现服务并预留 200 ms 匹配时间；
只有只读查询允许一次超时重试，运动命令从不自动重发。

本地纯逻辑测试通过 23 项（另 1 项需 ARM64 DDS 环境）。
部署前在机身原生 MC 消息环境运行新版逻辑，连续 5 次只读查询均返回
`ready / standing=true / switch_ready=true`，RPC 原始标志仍保留为 false。
姿态样本年龄 0.019–0.110 秒，两个运动请求标志均为 false。

### 最终镜像与现场验证

- 最终镜像：`primebot-q1:preset-readiness-20261127`，
  ID `4ee3b4b7351446399b129f0463f8502785609221a26eddbc60693cde8aefeb3a`。
- 最终镜像内 26 项测试全部通过，耗时 26.041 秒；包含电池回归、隔离域真实

- 部署时发现繁忙机身上的 ROS 初始化与服务发现会超出单次请求时限。
  已增加独立初始化握手：未就绪时快速返回 `initializing`，不发送或排队动作；
  发现四个服务后预留 1 秒完成匹配。先前部署检查失败时已恢复原容器。
- 最终部署保留 `expression/preset_postures/battery/imu/joints/model/mic/asr`
  八张卡片，沿用既有 Core URL、网络、挂载及重启策略，原容器保留用于回退。
- 预热后连续 6 次真机 `status` 均为 `ready / standing=true / switch_ready=true`，
  耗时 0.095–0.596 秒；20 次缓存 `info` 最大 0.096 秒。电池为 live，IMU 有有效朝向。
- Core 注册成功。初始化期间 HTTP 日志仍有其他请求断开产生的 BrokenPipeError；
  本卡片源码没有异常堆栈，连续状态查询通过。未修改其他卡片来掩盖这些日志。

用户随后明确授权用挥手或比心进行实机检查。本次仅发送一次 `wave`：

- 模式准备后请求 `SetMcPresetMotion(motion=3004, interrupt=false)`，无自动重试。
- 回执 `code=0, state=400, reason=0`，任务 ID `470748857184813056`。
- 实时运控报告同一任务的 `motion=3004`、`player_state=2`（播放中），进度持续增加；
  观测到 687 帧上肢关节反馈，右肘变化范围约 1.564 rad、右肩偏航约 0.873 rad。
- 观测结束时运控回到 1002、状态 100、切换就绪；直立、未摔倒、未提起、未移动。
  脚本没有另发复位或返回走跑指令。
- 用户现场回复“我实际观察到挥手动作执行了”。因此挥手获得了服务回执、
  运控/关节遥测和现场观察三方面验证。MCP 通用回执仍只声明接受请求，不据此
  把今后的所有动作自动标记为物理完成。
