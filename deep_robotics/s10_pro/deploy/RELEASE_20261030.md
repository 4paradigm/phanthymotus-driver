# S10 current-readiness and source cleanup — 2026-10-30

This version updates existing PR #451 through its original
`feat/s10-base-posture-timed-move` branch. It includes the later S10 local
changes and integration of upstream main at
`144b089390848fcf488a868f1c02cc51ee08fa46`.

## Runtime changes

- Canonical downward action is `sit_down`, consistent with `stand_up`.
  Saved workflows using `sitdown` or `stand_down` retain dispatch/completion
  aliases. The operation keeps the existing lie-down semantics.
- Automatic preparation and explicit `stand_up` use current readiness to rebuild
  a closed command worker under valid authorization. Ordinary command failures
  and transient preparation exceptions no longer impose a persistent manual
  software unlock. Failed tasks are never replayed or relabeled as successful.
- Monitor publication errors remain diagnostic instead of blocking motion.
  Task-store integrity failures still block affected work.
- Bounded stationary confirmation combines raw motion and advancing odometry
  evidence for small residual velocity. See [stop diagnostics](STOP_DIAGNOSTICS.md)
  for its thresholds, observation window and finite stop budget.
- Locomotion status and completion payloads are concise while `info` and the
  durable task store retain detailed evidence. The exact legacy Core
  `{ok: true, action_id}` receipt is accepted as endpoint acceptance; it does
  not prove physical success or lost-response deduplication.

Explicit card stop/disable, active-task exclusion, current faults, hardware
emergency stop, authorization scopes, request deduplication and finite command
execution remain respected. Core source and the overall Driver architecture
are unchanged by these S10 follow-ups. `sit_down` is a posture action, not a
separate unlock-only button.

## Source cleanup and verification

At the maintainer's request, all 51 S10-specific test/sample files (12,103
physical lines) and the selected-test manifest are removed. The pytest
requirement and obsolete test commands are removed from S10 release tooling.
Other robots' tests, runtime sources and manufacturer dependencies remain.
See the [test asset audit](TEST_ASSET_AUDIT.md).

The final run before removing tests had 1,341 passes, 35 existing failures and
one skip across S10; its selected release subset had 717 passes and one skip.
These are historical results, not a passing full-suite claim. The resulting
source is checked for catalogue/schema consistency, Docker COPY inputs,
service/container contracts, syntax and whitespace. It no longer includes the
S10 regression suite.

## Deployment boundary

This source update does not deploy to the robot, issue motion or change Core,
canvas state, site policy, containers, images or recorded tasks. Historical
site checks and earlier image deployments do not validate this new source.
A future deployment must identify the reviewed commit/image and separately
verify hardware behavior.
