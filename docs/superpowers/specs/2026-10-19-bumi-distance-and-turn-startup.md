# Bumi 按距离移动与旋转启动修复

> **历史方案（2026-10-21）：** 本文记录早期 RGB-D/IMU 融合设计，不是当前生产镜像的安装或部署指南。生产驱动使用直接 `pyrealsense2` 采集与实验性机身 IMU 测距，不打包或启动 RTAB-Map/EKF。当前行为以 [`noetix/bumi/README.md`](../../../noetix/bumi/README.md) 为准；独立视觉融合实验见 [`experiments/bumi_odometry/README.md`](../../../experiments/bumi_odometry/README.md)。

用户要求直接接入距离控制，取消“先通过真机里程计验收才可接入”的前提。基线 93164457；沿用当前工作树、PR #408 和直接实施方式。软件测试不代表已达到真机 ±5cm。

## 行为

- `loco_destination.move(distance_m)`：前进指定距离，范围 0.1–3m；不扩展倒退、横移或路径规划。菜单、参数映射、异步完成和说明同步注册。
- 订阅既有实验 `/bumi_odom/filtered` 与 `/bumi_odom/status`，只读，不启动相机或融合进程。两者须与驱动在同一 ROS domain；实验单独 domain 的用户须显式调整部署。
- 反馈必须为 `bumi_odom_odom -> bumi_odom_base_link`，有效有限位姿、非零四元数、正有限协方差、源时钟和接收时间新鲜，tracking 状态与 segment 稳定；缺失反馈同步拒绝。动作中丢失、重复/逆序、跳变、segment 切换均刹停报错。
- 起点朝向定义前进轴；用当前位置相对起点的投影计算进度，检查横向偏移和航向偏差，不把路程累计当作直线距离。SDK 命令是归一化速度；不得把它当作米/秒。
- 减速后刹停，在新反馈中观察不少于 0.5s 的静稳位置，误差在 ±0.05m 内才完成；过冲超限报错，不自动倒退补偿。无进展和总时限均有限。精度只表示里程计测量误差，实际精度待自测。
- 与 rotate/move/姿态动作共享当前 chassis reservation 和原子取消发布机制；一次只接收一个目标动作。`stop_move` 对两种目标动作生效；ACP 恰好一次终态；状态报告动作类型与实际位移。
- SDK 执行保持独立，不经 loco_servo 转发；只使用已有互斥与速度发布权交接。

## 旋转

现有固定 0.12s 短脉冲在启动延迟 0.2s 时连续三次无效。末段脉冲需要等待可测的同向转角启动，再给有界有效修正时间；等待上限 0.5s，仍无反馈进展即制动报错。到达角度带仍立即制动，保持 ±2° 原始反馈静稳完成条件。避免仅延长所有脉冲造成过冲；增加启动延迟和停转/取消回归。

## 范围与验证

新增小型里程计接收/距离控制模块；device.py 仅集成生命周期、schema、分派及共享 worker 终态。保持原旋转状态字段兼容。nav_msgs 在启用距离订阅时延迟导入；不改变镜像依赖或相机配置。覆盖 schema、前进轴、终点静稳、过冲、失跟/超时/跳变/时间倒退、取消、互斥、启动异常、ACP，以及旋转旧测试。相关 Bumi/control 测试全绿后独立复核，推送同一 PR；不部署或移动真机。
