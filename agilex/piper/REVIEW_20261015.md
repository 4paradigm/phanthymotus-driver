# PiPER ARM64 single-card review candidate — 2026-10-15

## Current interface

One Arm control card owns relative Cartesian Move, absolute/relative six-joint
targets, Set position, Reset, gripper control, Stop and passive Get status.
Skeleton, English parameters and optional live camera remain background outputs.
The current uncalibrated Move uses SDK end-frame axes and a linear translation,
preserving measured orientation. It is not the old six base-direction menu.
Arrays accept strict JSON text or native arrays. Absolute arrays allow null to
keep measured components; relative arrays use zero, never null. Zero relative
requests do not prepare hardware. Speed defaults to 1%, range 1–10%, with a
10 mm Move magnitude ceiling.

Supported stationary teaching exit/hold runs before resolving control targets.
Passive lifecycle/status and zero relative requests do not take over teaching.
Set position captures stable measured joints after that guarded takeover and
atomically saves a CAN-adapter/interface-bound return position. Reset returns
through MOVE_J; it never invokes ResetPiper, clears faults or assumes zero joints.
Invalid saved data does not silently fall back to a different configured pose.

Uncalibrated Pose/rotation and unconfigured Reset are hidden and rejected by the
backend. Candidate MOVE_P is closed until device/firmware/source/configuration-
bound physical acceptance is recorded. There is no automatic fallback/retry or
fault reset. See UNIFIED_CONTROL.md and PATH_VALIDATION.md for exact behavior.

## Physical evidence and remaining limits

Earlier Jetson user trials recorded completed relative Move, absolute/relative
joint operations and gripper open/close tasks. A later absolute joint request
`[1,0,0,0,0,0]` moved J2/J3 to their configured zero boundaries. The next
`[4,0,0]` tool-axis Move was rejected with TARGET_POS_EXCEEDS_LIMIT. At the
reported orientation this target was mostly downward in base coordinates.
The feedback does not identify the exact offending joint or prove a complete
inverse-kinematics diagnosis. Subsequent actuator requests were blocked before
target submission while the controller fault persisted. The driver did not
reset, clear or retry the fault; the user subsequently power-cycled the arm.

Those observations are limited acceptance evidence, not an all-functions pass.
Full directional reachability, stopping latency, saved-position return and
automatic teaching takeover still require recorded operator trials. Calibrated
absolute tip pose/rotation, MOVE_P and its Stop behavior remain unaccepted and
closed in the current deployment. Controller feedback is not external metrology.
No physical motion, mode, enable, disable or reset was requested during this
PR submission. Only arm 1 is in scope.
