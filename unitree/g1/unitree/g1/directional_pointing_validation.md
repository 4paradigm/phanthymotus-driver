# G1_23 方向示意：启用与验收

适用对象为五关节手臂、原厂固定假手的 G1_23。公开卡片是 `g1_directional_pointing`，业务动作只有 `point` 和按动作 ID 的 `stop`；框架的 `start/stop/info` 仍用于生命周期。本说明不包含 Skill。

## 1. 确认实际加载的版本与配置

部署 PR 机器人生成的镜像后，确认运行的是本 PR 的镜像及提交。旧容器内临时覆盖的源码不会自动进入新镜像，不能用历史 overlay 的成功记录证明 PR 镜像已经验证。

卡片默认关闭。在实际加载的完整 `config.yaml` 中启用 point，或通过 `CONFIG_PATH` 指向完整的持久配置。应核对下列设置：

| 项目 | 要求 |
|---|---|
| `plugins.g1_directional_pointing.enabled` | `true` 才会注册到工具目录。 |
| point solver / 左臂模式 | `bounded_ik` / `hold_measured`。 |
| 方向容差 / 指令速度 | 默认 `angular_tolerance_deg: 5.0`、`joint_speed_rad_s: 1.0`。 |
| 角度范围 | 默认偏航 `[-180, 180]`、俯仰 `[-90, 90]`；可通过配置缩小。 |
| 共享执行器 | `arm`、`loco`、顶层 `teleop_control` 已启用，`teleop_control.mode: live`。 |
| 模型配置 | `teleop_control.calibration_path` 指向本机使用的 G1_23 固定手 profile；镜像内随附路径为 `/work/motion/body23_fixed_hand.json`。 |
| 独立写入器 | `servo`、`servo_eef` 不与该卡共同启用。 |
| 回执 | 需要持久回执时设置 point 的 `receipt_directory`，路径须在可写持久卷内。 |

五关节向量依次为肩俯仰、肩侧摆、肩旋转、肘、腕滚，单位为弧度。`ik_reference_q_rad`、`verified_start_q_rad` 保留为模型参考/回退种子，不是固定起点门槛；如配置这些字段，须提供符合模型硬限位的完整五个数值。不要把另一台机器的现场采样当作通用出厂姿态。

按现场部署流程重新加载后，先用驱动 `tools/list` 确认工具名称，再刷新画布并手动拖入卡片。卡片不存在时先查是否仍加载旧镜像、是否加载了预期配置及是否启用 point；不要用空画布反复执行来判断部署结果。启用配置和重启不应同时触发 `point`。

## 2. 在画布执行并核对 ACP

由现场操作员确认模式、双臂空间及停机方式。运动门控接受新鲜常规运控 `500/0` 或 `500/1`，不要求静止时长。行走和手臂可同时提出请求，但本卡只控制双臂；先完成现场规定的静态用例，再按业务要求单独验收行走叠加用例。

1. 开启画布工程，选择 `point`，填写本次目标角及保持时间。例如 `20`、`20`、`1` 表示向机器人左前上方示意 1 秒。`+90/0` 指机器人左侧，`-90/0` 指右侧；它们只是目标方向，不保证当前姿态有可执行路径。
2. 保存返回的真实 `action_id`。`accepted` 只说明受理，不能记作运动成功。
3. 查找同一 ID 的 ACP `action_complete`，记录 `status`、`reason`、方向误差和到位保持证据。成功条件是已获得控制权、目标指令已下发、实测关节推算方向连续在阈值内满 `hold_s`、回到本次起点并完成交权。
4. 等 `completed` 后再换角度重复调用。每次使用新返回的 ID；无需人工恢复某个固定标定起点。
5. 在运动过程中用 `stop` 和当前 ID 进行停止用例。确认停止/交权结果及原动作唯一 ACP 终态；返回 `stopping` 时继续等待结果，不把请求受理当作物理停止。

默认保持时间范围 0.1–5 秒。框架的运动中断和项目停止会走停止流程。ACP 等待上限 120 秒仅约束 Core 等待，不是机器人停止回执。直接向驱动发 MCP 请求可以检验驱动接口，但不代替通过 Agent Core 发起、关联 ID、释放资源的完整验收。

## 3. 回执解释

| 字段或状态 | 含义 |
|---|---|
| `actual_direction`、`actual_yaw_deg`、`actual_pitch_deg` | 在 `torso_link` 中由实测右臂关节角计算的腕轴方向，不是躯干姿态。手臂一直下垂时数值接近并不证明反馈冻结。 |
| `angular_error_deg` | 模型腕轴与请求方向的夹角，不能与本体 IMU 的 pitch 直接比较。 |
| `arrival` / 完整回执 `arrival_diagnostics` | 方向阈值、连续保持时长、目标指令和控制权状态；达到一次角度阈值不等于连续保持成功。 |
| `left_max_error_rad` / 完整回执 `left_hold` | 左臂相对本次接管实测姿态的保持偏差。 |
| `external_accuracy: pending` | 外部量具精度验收尚未完成。 |
| `error` 或 `cancelled` | 分别按失败原因、取消和交权结果记录，不能解释为成功动作。 |

画布可能压缩较大的 ACP 结果。启用 `receipt_directory` 时，可在该目录读取 `<action_id>.json` 获取完整驱动证据；不要把读取回执替换为再次执行运动。没有反馈样本时方向可以为 `null`，仅凭这一点不能断言底层状态流完全停止。

有限 IK 无解、路径不通过、模式错误、反馈过期、控制权占用、到位超时和交权失败属于不同问题，应保留原始 `reason`。不要通过改别的卡或反复重发来掩盖失败。修改配置、几何或共享执行器后，重新验证受影响的用例。

## 4. 必须区分模型完成与外部精度

模型方向以固定手腕关节原点到 TCP 为指示轴，TCP 位于腕局部 X 轴 0.2 m。它不等于柔性手指指尖。若要验收物理指向误差，应以独立量具建立躯干坐标基准，测量该轴线相对请求方向的夹角，同时记录安装误差和测量不确定度。

默认 5° 是反馈模型的业务完成阈值，不是已经测得真机绝对误差 ≤5°。同一套 FK 的计划方向与反馈方向一致不能替代外测。只有保存了实际版本对应的完整 ACP 结果或独立测量证据，才能将相应验收项标为通过。

几何模型保留关节硬限位和 3 mm 模型间距。指令路径证明固定本次左臂姿态；执行期间检查同一 LowState 样本的两臂实际姿态。该检查不证明两个反馈样本之间、停止过程或变化腿部的动态间距，也不包括外部物体。详细证据见[几何说明](directional_geometry/README.md)。

## 5. PR 镜像验收记录

至少记录以下项目，由机器人 master 与负责老师确认：

| 用例 | 应留证据 |
|---|---|
| 版本和注册 | PR 提交、bot 镜像、实际配置版本、工具目录存在。 |
| 普通方向及跨身左侧方向 | 请求角度、起点、动作 ID、唯一 ACP 终态、现场观察、回程和交权。 |
| 重复调用 | 不同角度/保持时间的各次 ID 和结果，无固定起点依赖。 |
| 中途停止、重复停止、项目停止 | 停止结果、交权确认、没有重复 ACP 终态。 |
| 被拒绝的请求 | 非法角度、不可执行几何路径、占用或错误模式等原始原因。 |
| 外部精度及行走叠加 | 独立测试记录；未完成的项目明确记为待验收。 |

记录只包含真实观测，不填推断的成功状态。若要回退，先通过该动作 ID 停止并确认现场状态，再按既有部署流程恢复镜像和完整配置；停止容器或关闭网页不能代替手臂交权确认。
