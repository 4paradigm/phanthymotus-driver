## 2. 真机验收场景

在画布上按顺序执行，每个场景单独存事件日志：

| 场景 | 输入 | 通过标准 |
|---|---|---|
| 启动 + 三问 | `请激活技能 g1-shift-handover，准备交接。` | `activate_skill` → `posture {}` → `switch_mode__get_current_mode {}` → 三问逐字 TTS；无 `led`/相机/运动调用 |
| 草稿 | 回答本班工作/问题/待办 | assistant content 出现完整「交接草稿（待确认）」含【设备读取】【用户陈述】【待核实】；相机问题标「用户报告，未核实」 |
| 修改不提前确认 | 要求改待办，并声明未确认 | 更新草稿并再次请求确认；**不**输出「交接记录（用户已确认）」 |
| 确认 | `确认最新草稿，完成这次交接。` | 输出「交接记录（用户已确认）」，保留修改内容；无创建文件/上传/发送 |
| 取消 | `取消本次交接，不提交。` / `结束本次交接。` | 同轮 TTS 仅 1 次，文本为「本次交接已取消，未提交」，无追问 |
| 新开一份 | `准备新一份交接。` | 重新读姿态/模式并重新逐字三问，不归属取消分支 |

取日志：连 `wss://<host>:15678/ws/motus?token=…` 收 `mcp_call` / `mcp_result` / `turn_end`，
按 `turn_end` 截断并落盘；token 不写入日志。

## 3. 已知开放项（不计为通过）

- 组合句 `结束本次交接，换新一份。`：4 次测试 3 次判为「新开一份」、1 次判为取消，模型判定不一致。
- `准备新一份交接，之前已确认的记录保持不变。`：未走取消，但只追问变化项，未重新逐字三问。
- 历史失败轮（v1.0.3 刷 `led__set`；v1.1.0 未激活且替用户编造回答；v1.1.1 取消轮双播报）
  1.1.3 的当前演示流程未复现这些行为；不能据此保证任意自然语言输入都稳定。
