# 工位巡检拍照留档

## 场景与输入

机器人已停在待记录的工位前，用户要求为该工位拍照留档。工位名称由用户提供，是记录标签，不代表已经自动识别或到达该位置。本技能只完成一次现场照片采集和结果回执。

触发示例：“给装配工位 A 拍照留档”“执行工位巡检拍照留档，工位是检测台 2”。

必需输入为非空工位名称。没有名称时，只询问“这次记录哪个工位？”，等待回答后再拍照。用户取消或更换任务时停止本次流程。

## 工具选择

1. 使用当前工具列表中 vision_capture 的实际完整名称，不猜 MCP ID、文件路径或相机 Topic。
2. 若工具被拆分为 action 子工具，分别使用真实的 `vision_capture__info`、`vision_capture__capture_photo` 对应工具，按其实际 Schema 传参；不要把 action 再塞进不接受它的子工具。未拆分时调用 vision_capture，分别传 `action: "info"` 和 `action: "capture_photo"`。
3. 当前上下文没有该工具，或有多个相机无法确定选择时，先说明缺少执行绑定或询问相机选择；不得假装已经拍照。提示检查决策核心到 vision_capture 的执行绑定。

## 执行步骤

1. **检查相机**：调用 info。解析真实返回值；MCP 的 text 内容若为 JSON，应先解析。HTTP 成功、外层 code=200 或工具调用已接受，都不单独构成业务成功。
2. 要求业务返回 `ok: true`，且 `latest_frame_age_s` 是 0 到 2 秒之间的有效数值。无帧、数据过期、字段缺失或状态无法确定时结束本次采集，说明原因并提示检查相机。`active_recording` 非空时告知已有录像任务，等待它完成；不得调用 stop 中断其他任务。
3. **拍一张照片**：调用 capture_photo 一次。不得调用录像、移动、导航、机械臂或自动重试。超时或断线时说明“未确认本次拍摄结果，请先核对保存目录”，避免重复拍摄。
4. **核实结果**：只有业务 `ok: true`、`media_type: "photo"`、`file_path` 为非空绝对照片路径，且 `frame_age_s` 为 0 到 2 秒之间的有效数值，才能报告“相机已保存照片”。路径和 captured_at 必须逐字来自本次调用结果；缺失时不得拼接、推测或使用之前的照片代替。
5. **文件检查**：若当前上下文已有可访问该文件的读取、文件信息或下载工具，则使用真实路径检查本次照片确实存在且非空；能读取图像时再检查文件能够打开。权限不足或工具不可用时，如实写“相机返回已保存，尚未独立核验文件”，不要更改访问权限或声称已经打开。不能读取照片也不能声称已识别现场内容。
6. **输出回执**：包含工位、结果、相机原始采集时间、照片路径和文件核验状态。相机时间没有时区时标注“相机原始时间，未声明时区”，不要直接当作北京时间。最后按主系统协议结束任务。

## 回执格式

工位：<用户提供的名称>
结果：<已保存 / 失败 / 结果未确认>
采集时间：<本次 captured_at 原值；缺失则写未提供>
照片路径：<本次 file_path 原值；失败且无有效路径则写无>
文件核验：<实际核验结果，或尚未独立核验>
原因：<失败或未确认时给出简短原因；正常时可省略>

## 完成标准

正常流程先查状态、后拍一张，回执有真实路径；缺名称先补充；工具不可用、无帧、过期、返回失败或没有有效路径时不报成功。该记录证明完成了照片采集，不作设备正常、工位合格或照片质量达标的判断。
