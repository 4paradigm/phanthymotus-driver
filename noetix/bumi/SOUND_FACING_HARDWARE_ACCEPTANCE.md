# Bumi Sound Facing 真机验收计划

2026-11-11：**全部物理项目未执行，本轮未连接、不通电、不允许真实运动。** 本文是后续由设备负责人批准并由现场操作者监督执行的计划，不是自动部署/运动脚本。

Agent 与 Canvas 只可在独立操作员 Ed25519 签名授权内 enable/renew。私钥留在离机受信任工作站；公钥只读固定在 Driver，且 Agent 不得拥有改写 Driver/公钥或 Docker/宿主的权限。操作员已确认当前尚未限制这些管理权限，部署隔离仍为阻塞。软件通过不代表声学精度、机械效果、物理停止或 ARM64 镜像已验收。

## 进入现场阶段前

- 先关闭权限部署边界：记录 Agent 工具和容器权限配置，确认其不能读取操作员私钥，不能通过 Bash、Docker socket、文件写入或容器管理改写验证器/公钥；缺证据则 NO-GO，不进入运动阶段。
- 由负责人确认 Noetix Bumi EDU Max、固件、电量、供电和物理停止手段可用；此确认留待后续，本轮不尝试。
- 核对候选源码/补丁哈希、Driver 基线和版本、Core 版本、ARM64 镜像 digest、构建导入及容器 Fake Controller 证据；镜像尚未构建时不得跳过。
- 确认专用测试容器名、端口、目录、数据库、配置副本及 ROS Domain 无冲突。只读记录原容器、挂载、服务状态，禁止覆盖原配置/数据卷/他人文件。
- 不停止、禁用或覆盖共享服务，包括 `noetix-video-capture.service`。本 Card 不需要相机；现有 main 按默认 camera 配置可能停厂商服务，因此候选**独立配置**必须关闭 camera、visual_odometry、vision_capture，并设 `disable_vendor_capture_service:false`。不得直接运行全默认共享配置。
- 只启用本次需要的 state、loco、sound_direction、bumi_sound_facing；mic 仅在验证语音链路必要且不冲突时开启。loco_servo 必须 idle，不启动 navi、行走、舞蹈或动作回放。
- 现场有足够平整、防滑、无障碍空间，身体与线缆旋转范围净空；一名操作者持续监管，能立即使用物理停止手段，不无人值守。
- 不调用会加载 .env、可能发布镜像/登记资源的 build.sh，不擅自发布部署。

## 阶段 1：只读发现和声源观察

1. 使用实际平台发现工具和 namespace，核对 MCP URL、tools/list、ROS Domain、DDS profile、QoS；不要猜 IP。离线测试域 197/198 不等于现场配置，厂商 SDK DDS 与 ROS bridge 配置不能混用。
2. 确认 sound_direction、loco_relative_move、bumi_sound_facing 和十个 action（含 prepare_authorization、authorize_follow、cancel）。核对注册默认关闭策略及当前候选已显式启用注册。
3. 只调用 start/info，确认 enabled=false、session_id=null、无转身；配置保存、Canvas 初始化、Driver 重启也不自动启用。
4. 从前、左、右、后方说话，记录完整 fresh/no_event/stale；读取原 sound_direction.info 核对 worker、front/right 标定。
5. 核查采集窗口非零、递增、实际窗口长度与年龄、主机/SDK 时钟偏差，独立对齐真实音频与采集时间，不能将发布时间或接收时间当采集时间。
6. 验证环境噪声、风扇、机器人播音、反射、多声源和静音；记录方向误差、拒绝原因、是否会持续误报同一方向。不能仅靠稳定统计断言目标是操作者声音。
7. 确认 Core 未认证 API 请求被原控制拒绝，未连线 Card 不向 Agent 暴露，受限 viewer/bot 来源按既有规则拦截；无需新增匿名入口。

方向符号、标定、时间含义或噪声表现不满足时停在本阶段，不用提高年龄/分散阈值掩盖。

## 阶段 2：明确启用与低风险单次转向

1. 先确认现场监管与停止手段，按 SOUND_FACING.md 完成 prepare → 离机操作员签名 → authorize_follow，再由 Agent/Canvas enable_follow。记录 session_id、会话与授权剩余期限；会话默认 30 s，操作员授权最多 300 s。受控调用方可每 10 s renew_follow，但不能越过授权期限；状态读取不续期。
2. 前方声源应不运动。左侧稳定约 +20–30° 应向左，保持只有一个 turn_action_id；独立量角/视频记录实际转角、用时、滑移与停止。
3. disable 后等待本地终态及连续安静、motion_reserved=false，再明确 enable 测右侧 -20–30°。
4. 同样由有现有权限的 Agent 发标准 enable/renew/disable，确认与 Canvas 行为一致。Agent 不能通过 start/config、旧 session_id、重复 enable 或恢复配置自动续跑。
5. 记录 accepted/running、本地 terminal、final_error_deg、settling、新采集边界。SDK 写零、IMU done、HTTP 成功均不能代替真实物理测量。
6. 运动中 disable 应撤销会话，仅停止自己动作；记录独立物理停车时间/距离。无法确认则使用物理停止，由负责人恢复，不继续下一次动作。

方向相反、意外平移、重发、摆动或停不可靠时立即结束，不升高速度或绕过保护。

## 阶段 3：连续跟踪和大角度

- 同一受管理会话按左→前→右→前→左移动声源，至少 6 次转向，含累计超过 360°；会话内不因累计角度截断。
- 每次确认匹配 terminal→settling→整体在稳定后采集的新窗口，旧窗口重播不触发下一次，turning 不产生第二请求。
- 验证声源消失、短促声、左右跳变、多源和运动自身噪声；应暂停或故障，无旧方向无限重试。
- 小角度及停止验证后再由现场负责人批准 ±90°、±150°、接近 ±180°。记录正后方符号边界；单次仍遵守原 Driver 范围和超时，不能拆成重复命令绕过保护。
- 停止续期：期限到达应撤销/取消，旧 ID 不可续活；故障恢复后仍要明确 enable。自动续期程序也须可撤销并有人管理。

## 阶段 4：停止、故障及生命周期

| 场景 | 现场验收要点 |
|---|---|
| turning 中 disable/stop/平台中断 | 只取消本 Card 动作，终态+安静后释放，记录实际停车 |
| 别的动作先占用 | enable 拒绝，不停止对方；旧 owner/ID 取消不影响其运动 |
| 本会话占用时另一动作请求 | 对方被拒；全局人工 stop 可中断本会话且不自动恢复 |
| 续期管理停止 | 默认 30 s 内到期撤销，必须重新 enable，不因 info/声源流续期 |
| 输入失流/过期、标定失效 | 无新请求，撤销当前会话；不无限重试 |
| 非 walking/protection=26 | 拒绝或撤销，不自动起身、切模式或解除保护 |
| 制动异常/终态缺失/不安静 | fault 保留占用；不把软件 released 当物理停止 |
| 配置变化、多次启停、重启 | 无自动启用、线程/ROS 资源泄漏或旧 ID 干扰 |
| ACP 网络异常 | 内部 turn 不依赖网络回调；公开 rotate 的 Core 基线 early/duplicate 问题另行记录 |

先在 Fake Controller 注入危险故障，真机只使用负责人批准且可恢复的方式，不主动制造危险保护状态。未确认停止不能靠容器重启清除占用后再启用。
