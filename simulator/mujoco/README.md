# MuJoCo 仿真调试卡片

这张卡片让用户从 Phanthymotus 主画布打开内嵌工作台，创建、观看和控制服务器上的真实 MuJoCo 仿真会话。机器人网格画面由服务器渲染，物理步进和策略推理也在服务器执行。

它与主仓库的“动作学习”卡片共用 Motion service：动作学习负责动作数据、SuperMimic 训练、评测和模型导出；仿真调试负责会话、控制权、物理诊断和录制回放。无需给每个动作添加一张卡片。

| 项目 | 值 |
| --- | --- |
| Driver ID / 镜像名称 | `simulator-mujoco` |
| MCP 工具 | `simulation` |
| Driver MCP 地址 | `http://<driver-host>:15712/mcp` |
| Motion service 默认端口 | `15732` |
| 环境安装器默认端口 | `15734` |

## 配套版本与边界

本目录需要与主仓库的 SuperMimic 接入 PR 配套使用。该 PR 提供 `actucore/motion_service`、`actucore/motion_environment`、动作学习卡片，以及工作台的通用 `config` 桥。已有 `motus.workbench/1` 弹窗但缺少 `config` 桥的旧 Core 可以加载页面，却不能完成内嵌连接配置；不能据此判定安装完成。

- 主仓库完整说明：`docs/supermimic/USER_GUIDE_ZH.md`、`docs/supermimic/REVIEW_GUIDE_ZH.md`。
- 训练与服务部署：主仓库 `actucore/motion_service/README.md`。
- 无环境服务器的引导安装：主仓库 `actucore/motion_environment/README.md`。
- 本 Driver 不安装 SuperMimic、不在本地运行 MuJoCo，也不控制实体机器人。
- 当前正式接通的 SuperMimic 策略合同是 G1 的动作跟踪。任意机器人、速度/方向控制、导航和抓取不在本 PR 范围内。
- 联调样例只能证明链路可运行。现有短训样例策略仍会摔倒，不能作为合格运动策略。

## 连接前需要准备什么

管理员应先确定三种不同地址，避免把 SSH 地址填进工作台的服务地址：

| 连接 | 谁使用 | 用途 |
| --- | --- | --- |
| SSH：`<user>@<gpu-host>` 及 SSH 端口 | 管理员 | 登录服务器、部署服务、检查日志 |
| Motion HTTP(S)：`http://<service-host>:15732` 及 Motion token | 两个卡片的后端 | 训练、读取模型、创建仿真、取得渲染帧 |
| 安装器 HTTP(S)：`http://<manager-host>:15734` 及独立安装器 token | 两个卡片的后端 | 查找预登记环境、检查和安装服务 |

工作台中的服务地址必须是 **Driver 进程或容器可访问的地址**。浏览器能访问该地址并不足够。容器里的 `127.0.0.1` 指该容器自身；把开发电脑上的 SSH 隧道地址填到远端 Driver，不会转发到开发电脑。

本 Driver 的部署片段采用 Linux `network_mode: host`，可连接同一主机回环地址上的服务。其他拓扑应由管理员提供可路由的私网地址或 HTTPS 代理。安装器创建的独立容器默认不向宿主机发布端口，Driver 必须能访问它所在的容器网络；跨主机部署需要另外配置网络或受保护代理。

SSH 私钥只留在管理员自己的管理入口，不上传到卡片。工作台 token 与 SSH 密钥也不是同一个凭证。

## 管理员部署 Driver

通过本仓库已有的 Driver 构建与安装流程选择 `simulator/mujoco`。`driver.yaml` 声明了 `common` 构建依赖，Dockerfile 只打包 MCP 插件与工作台，不需要 GPU。构建方式遵循根目录 [Driver 开发说明](../../README_dev.md) 与 `build.sh`；配置镜像仓库的构建流程可能同时推送镜像。

容器需运行在已有 ROS2/Agent Core 部署中，并能通过 MCP 被 Core 访问。共享运行时默认向同机 `https://localhost:15678` 注册，注册的 MCP 地址为 `http://localhost:15712/mcp`；跨主机时需按平台的 MCP 管理流程登记 Core 能访问的 Driver 地址。

部署片段 [deploy/service.yml](deploy/service.yml) 支持以下环境变量：

| 变量 | 配置内容 |
| --- | --- |
| `MOTION_SERVICE_URL` | 已有 Motion service 地址；也可在工作台手动设置 |
| `MOTION_API_TOKEN` | 已有 Motion service 的访问凭证 |
| `MOTION_ENVIRONMENT_URL` | 可选，环境安装器地址 |
| `MOTION_ENVIRONMENT_TOKEN` | 可选，安装器访问凭证，与 Motion token 分开 |
| `SIMULATION_STATE_HOST_DIR` | 宿主机私有绑定目录，默认 `/opt/phanthy-motus/data/simulation` |

部署片段把私有绑定目录挂到容器 `/var/lib/phanthymotus/simulation`，并设置 `SIMULATION_WORKBENCH_STATE_DIR` 指向它。管理员应预先建立该目录并限制读取权限：

```sh
install -d -m 700 /opt/phanthy-motus/data/simulation
```

直接运行 Python 时，`SIMULATION_WORKBENCH_STATE_DIR` 默认是 `~/.local/state/phanthymotus/simulation`。环境引用及实际服务凭证以权限 `0600` 的私有文件保存；手动连接配置由主页面的共享配置管理。已保存凭证不会返回工作台 iframe，页面只显示“凭证已保存”。

启动 Driver、启动项目或打开工作台都不会自动开始物理运行或训练。

## 从主页面打开并连接

1. 在主页面加载或添加 `simulator-mujoco` 的 `simulation` 卡片。
2. 将卡片操作设为 `ui` 并执行，主页面会弹出“仿真调试”。这里是主页面内嵌工作台，不是另一个独立产品页面。
3. 点击右上角 **连接**，选择下面任意一种连接方式。

### 已有 Motion service

展开 **手动连接服务**，填写完整服务地址和访问凭证，点击 **保存连接**。成功后机器人配置和模型列表来自该服务的真实目录。需要验证时，点击 **测试当前连接**；该按钮检查已保存的当前连接，不会先保存尚未提交的输入框内容。

再次打开连接弹窗时，凭证框留空。留空保存会沿用原凭证；输入新值可以更新凭证。

### 使用页面中已准备的环境

如果两个卡片后端都已配置安装器地址及凭证，在 **已准备环境** 选择同一个成功安装任务，点击 **连接此环境**。两卡分别保存同一 `environment_job` 引用，由各自后端向安装器取得服务凭证；浏览器不会取得这份凭证。

如果服务器尚无仿真环境，应先由管理员在服务器部署安装器并登记目标，再到 **动作学习 → 环境** 检查或安装，查看真实阶段和日志。仿真调试的连接弹窗负责选择已准备环境，不包含完整安装流程。前端不能直接登录一个任意 SSH IP 并安装驱动、Docker 和 NVIDIA runtime；这些基础条件由管理员准备。

连接环境后，原来的会话仍属于原服务。更换服务器前需交出本卡窗口仍持有的控制权；切换不会销毁旧服务上的会话。连接为 bundle 共享配置，同一 bundle 的多个卡片实例会使用同一服务。

## 第一次创建场景

在“调试会话”页面右侧依次选择 **机器人**、**策略**，再点击 **创建并打开**。新会话暂停在初始状态，点击 **开始运行** 才推进物理。

| 选择方式 | 实际行为 | 适合检查什么 |
| --- | --- | --- |
| 不加载策略 → 保持姿态 | `pd_hold`：PD 控制器尝试保持配置的初始关节姿态 | 模型、重力、接触及基础执行器参数；不保证机器人能平衡 |
| 不加载策略 → 自由物理 | `free_physics`：不施加策略/PD 目标，按物理环境演化 | 重力、碰撞与模型资产 |
| 选择一个策略版本 | `policy`：加载该版本的 ONNX 与绑定的参考动作 | 实际学到的动作跟踪效果 |

选择策略后，工作台使用这个版本对应的机器人和参考动作，不能把别的 NPZ 临时替换进会话。版本显示“已评估”只表示运行过评估，不表示动作质量达标。若要导入动作、训练新版本、检查或导出模型，使用配套“动作学习”卡片。

## 观看、控制与诊断

- **打开观看**：接入已有会话，仅观看状态和画面。动作学习发起的试跑也会列在这里。
- **取得控制**：当前无人控制时取得控制权。**接管控制**会显式转移其他窗口的控制权，同时暂停会话；旧窗口后续的控制请求被拒绝。
- **开始运行 / 暂停**：连续运行或暂停。动作片段完成后显示“动作完成”；**再次运行**会先重置再运行。
- **重置**：恢复初始状态，保持暂停。它不同于训练任务的重新训练。
- **交出控制**：立即暂停并交出控制，保留会话供继续观看或重新取得控制。
- **结束会话**：只有当前控制者可以关闭服务器会话。观看者不能通过关闭自己的页面销毁会话。
- **诊断**：单步、关节数值、接触和刚体状态。扰动参数作用于仿真刚体，用于观察物理响应。

每个窗口有独立 `view_id`；控制者每 5 秒续约。关闭工作台、关闭浏览器或断网后，服务在 20 秒租约到期后的检查周期内暂停，**不是关闭瞬间立即暂停**。观看窗口关闭不影响控制者。项目停止只暂停本插件仍拥有控制权的会话；后台训练与环境安装任务有独立生命周期。

## 真实画面与录制回放

默认 **MuJoCo 画面** 展示服务端离屏渲染的机器人网格和场景。拖动旋转、滚轮缩放，**居中**把镜头移到机器人当前位置；暂停时仍可调整视角。

页面串行请求图像，目标上限为 20 帧/秒，实际速度受渲染及网络影响。运行或交互时使用最高 `640 × 480` 的图像，暂停且视角稳定后使用最高 `960 × 640`；实际尺寸按工作台长宽比缩放。暂停空闲时每两秒检查状态，切换到其他浏览器标签时停止画面请求。

**诊断**面板里的 **骨架**与 **碰撞几何**是手动选择的检查视图。渲染失败直接显示错误，不会自动换成诊断绘制以掩盖失败。

进入录制面板后，点击 **开始录制**，运行或单步仿真，再 **结束录制**。录到的状态可逐帧回放；回放图像由服务端从指定记录渲染，不改变实时会话的物理状态。切回实时后继续查看当前仿真。

当前录制用于仿真状态回放，**没有接通“录制 → 合格训练动作 NPZ”转换**。录到摔倒也不意味着得到可用于学习稳定动作的示范。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 卡片能打开，连接弹窗报不支持操作 | 核对配套 Core 的通用工作台 `config` 桥已部署；仅更新 Driver 不够 |
| 连接超时或拒绝连接 | 从 Driver 所在网络检查 Motion 地址和监听范围；区分浏览器、Driver 容器、GPU 服务器三个网络位置 |
| 认证失败 | 使用 Motion token 连接 Motion service，使用安装器 token 配置安装器；更换 token 后保存连接 |
| 已准备环境列表为空 | 检查后端 `MOTION_ENVIRONMENT_URL/TOKEN`，并确认安装任务成功；单纯“检查通过”不产生可连接安装结果 |
| 没有机器人或策略可选 | 检查当前服务加载的 `profiles.json`、数据目录，以及训练是否确实产生模型 |
| 画面无法渲染 | 在服务器核对 MuJoCo/EGL 及渲染 GPU 配置；CPU 进程能加载模型不代表 EGL 可用 |
| 操作按钮灰色 | 先取得控制；若其他窗口接管，刷新状态后决定是否显式接管 |
| 第一时间报目标关节限位 | 核对 Motion service 已包含本次执行器语义修复。不要删除所有限位或随意截断策略输出 |
| 不再报错但机器人摔倒 | 检查真实策略效果和评测；PD 保持、样例训练或“已评估”都不保证稳定平衡 |

## 开发和验证

在 Driver 仓库根目录执行：

```sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest \
  tests/test_mujoco_remote_card.py tests/test_mujoco_environment_binding.py -q
```

需要浏览器/物理验证的可选测试会检查本机 Chrome、MuJoCo 和相邻主仓目录；缺少时明确跳过。非相邻检出可通过 `MOTION_TEST_MAIN_ROOT=/absolute/path/phanthymotus` 指定主仓，非默认 Chrome 路径可通过 `MOTION_TEST_CHROME` 指定。插件单元测试不代表已经验证了目标服务器 GPU、EGL 或训练质量，服务器验收记录见配套主仓 review 文档。

`workbench.html` 是生成文件。源文件在主仓 `actucore/plugins/motion/ui/`，修改后从主仓运行：

```sh
python3 actucore/tools/build_motion_workbenches.py \
  --driver-output /absolute/path/phanthymotus-driver/simulator/mujoco/workbench.html
```

加 `--check` 可校验两仓产物是否一致。页面脚本、样式与诊断绘制均打包在 HTML 内，通过标准工作台桥读取 JPEG，不加载外部脚本。
